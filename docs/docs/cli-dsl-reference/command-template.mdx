# Command template

Command templates are used to map the input to any desired command.

# Interpolation forms

There are two of them, and they read differently on purpose:

* `@{name}` — **plain interpolation**. The value of `name` is dropped into the command as-is
  (`true`/`false` for a flag, the value for an arg, the empty string for an arg the user left out).
* `@{name ? "..."}` — **conditional mapping**. The quoted text is emitted only when `name` is
  *defined*: a flag that is set, or an arg with a value. Otherwise the whole mapping disappears.
  Inside the quotes, `{}` stands for the value, so you pick the joiner yourself
  (`--today-is={}`, `--today-is {}`, `-t{}`, or no `{}` at all).

Prefixing the name with `!` (`@{!name ? "..."}`) inverts the condition. This only makes sense for
flags and boolean constants.

# Mapping flags

<MappingFlags/>

When executing `foo`, the flag `goodDay`'s value will just be interpolated into the string

When executing `bar`, the flag will decide whether the string `today-is-a-good-day`
is interpolated, or not

When executing `baz`, the effect will be the same as for `bar`, only the flag will be inverted
```bash title=Console
$ hello-world foo
Hello World false

$ hello-world --goodDay foo
Hello World true

$ hello-world bar
Hello World

$ hello-world --goodDay bar
Hello World today-is-a-good-day

$ hello-world baz
Hello World today-is-NOT-a-good-day

$ hello-world --goodDay baz
Hello World
```

# Mapping args

The same two forms apply to args — the difference is that `{}` is where the value lands.

<MappingArgs/>

```bash title=Console
$ hello-world Tuesday foo
Hello World Tuesday

$ hello-world Tuesday bar
Hello World --today-is=Tuesday
```

Because a mapping is dropped whole when the arg is undefined, an optional arg costs no extra
plumbing — the option name goes with it:

```clidsl
greet(name: arg?, greeting: arg?) {
    action <% say @{greeting ? "--greeting {}"} @{name ? "-n{}"} %>
}
```

```bash title=Console
$ greet
say

$ greet --name Ada
say -nAda

$ greet --name Ada --greeting Hi
say --greeting Hi -nAda
```

:::note
To write a literal `{}` inside a mapping, escape the brace: `\{}`. A literal `"` is `\"`.
:::

# Argument quoting

Values that come from the user — `arg` parameters and the unmatched-args passthrough — are
automatically wrapped in single quotes when interpolated into the command. Each one reaches the
shell as a single, literal argument, so spaces and shell metacharacters in a value cannot
word-split or inject:

```clidsl
greet(name: arg) {
    action <% echo Hello @{name} %>
}
```

```bash title=Console
$ greet "Ada Lovelace"
Hello Ada Lovelace          # the value stays one argument

$ greet '; rm -rf ~'
Hello ; rm -rf ~            # the value is printed, not executed
```

Because of this you no longer need to hand-quote interpolations (`'@{name}'`) — doing so just adds
redundant quotes.

:::note
Only user input is quoted. `const` values and mapping text are trusted text you wrote in the DSL,
so they are interpolated verbatim (a constant can still hold, say, a shell fragment).
:::

:::caution
Quoting uses POSIX shell single quotes, so isolation applies to the default `*NIX` shell (`/bin/sh`).
On Windows (`cmd.exe`) single quotes are not argument delimiters.
:::
